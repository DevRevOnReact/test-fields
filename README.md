# Поля

[![CI](https://github.com/DevRevOnReact/test-fields/actions/workflows/ci.yml/badge.svg)](https://github.com/DevRevOnReact/test-fields/actions/workflows/ci.yml)

Небольшая лента публикаций с серверным рендерингом и формой создания поста.

Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4, Zod 4.
Данные — [JSONPlaceholder](https://jsonplaceholder.typicode.com/).

## Запуск

Рекомендуется Node.js 22 LTS, минимум — 22.12. Версия для CI указана в `.nvmrc`.
Нужны npm и доступ сервера к JSONPlaceholder по HTTPS. Ключи и `.env` не требуются.

```bash
npm ci
npm run dev
```

Открыть [localhost:3000](http://localhost:3000).

Для production:

```bash
npm run build
npm start
```

## Проверка проекта

```bash
npm run verify
```

Команда последовательно проверяет форматирование, ESLint, TypeScript, запускает unit-тесты
и production-сборку. Любая ошибка останавливает цепочку. Предупреждения ESLint также считаются ошибкой.

| Команда                | Назначение                                                  |
| ---------------------- | ----------------------------------------------------------- |
| `npm run format`       | Отформатировать файлы                                       |
| `npm run format:check` | Проверить форматирование без изменений                      |
| `npm run lint`         | ESLint без допустимых предупреждений                        |
| `npm run typecheck`    | Сгенерировать типы маршрутов Next.js и проверить TypeScript |
| `npm test`             | Запустить Vitest один раз                                   |
| `npm run test:watch`   | Запустить тесты в режиме наблюдения                         |
| `npm run build`        | Собрать приложение                                          |
| `npm run verify`       | Выполнить все проверки выше, включая сборку                 |

GitHub Actions запускает `npm ci` и `npm run verify` на Ubuntu при push, pull request
и ручном запуске. У workflow только права чтения репозитория, версии Actions закреплены
по SHA. Новая проверка той же ветки отменяет устаревший запуск.
Unit-тесты подменяют внешние запросы, а страница рендерится динамически:
CI не зависит от доступности JSONPlaceholder.

## Архитектура

| Модуль                                                    | Ответственность                                                                 |
| --------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `src/app/page.tsx`                                        | Композиция страницы и чтение параметров URL                                     |
| `src/components/post-list.tsx`                            | Server Component: запрос готовой ленты и отображение её состояния               |
| `src/components/post-card.tsx`, `pagination.tsx`          | Карточка публикации и навигация                                                 |
| `src/components/post-form.tsx`                            | Клиентская граница: `useActionState`, pending и управление фокусом              |
| `src/components/post-field.tsx`, `post-form-feedback.tsx` | Поля с подсказками и ошибками; результат отправки                               |
| `src/app/actions.ts`                                      | Server Action: извлечение FormData, валидация и создание поста                  |
| `src/lib/post-feed.ts`                                    | Загрузка постов и авторов, объединение данных, обработка недоступного источника |
| `src/lib/pagination.ts`                                   | Чистые функции проверки номера страницы и выбора записей                        |
| `src/lib/posts.ts`                                        | Серверный HTTP-клиент: GET/POST, тайм-аут, статус и проверка JSON               |
| `src/lib/post.ts`                                         | Схемы ответа API и типы публикаций/авторов                                      |
| `src/lib/post-schema.ts`, `post-limits.ts`                | Серверная валидация и общие ограничения для схемы и формы                       |
| `src/lib/form-state.ts`                                   | Типизированные состояния idle/error/success                                     |

Чтение: `PostList → getPostFeed → HTTP-клиент → JSONPlaceholder`.

Создание: `PostForm → submitPost → Zod → HTTP-клиент → состояние формы`.

Серверные модули защищены импортом `server-only`. В клиентскую форму из модели
передаются только типы; Zod и HTTP-клиент для чтения данных ей не нужны.
Успешное состояние формы обязательно содержит пост, ошибочное — сообщение.

## Поведение и ограничения

- Лента отображает по 6 записей; номер страницы хранится в URL.
- Заголовок: 3–120 символов, текст: 10–3000 после удаления крайних пробелов.
  HTML-ограничения помогают пользователю, Zod независимо проверяет данные на сервере.
- При ошибке исходный ввод сохраняется. После успеха поля очищаются.
  Ключ формы меняется после ответа, чтобы корректно восстановить uncontrolled-поля React.
- На время отправки поля и кнопка отключены. Ошибки связаны с полями через ARIA,
  фокус переводится на результат. Есть ссылка пропуска навигации и поддержка reduced motion.
- При недоступности авторов лента показывает ID вместо имени. Ошибка постов выводится
  с возможностью повторной загрузки. Неизвестные страницы получают 404.
- Запросы используют `no-store` и тайм-аут 10 секунд. Ответ внешнего API проверяется Zod.
- Для небольшого набора данных пагинация выполняется над полученным массивом.
  При большом объёме её следует перенести в API или базу.
- Лента приходит готовым HTML без потоковой границы Suspense и доступна без JavaScript.
  Форму также можно отправить без клиентского JavaScript.

JSONPlaceholder **имитирует создание и не сохраняет новые посты**:
[официальное описание](https://jsonplaceholder.typicode.com/guide/).
Результат POST показывается рядом с формой и исчезает после перезагрузки.
Общая лента не изменяется. Это объясняется в интерфейсе до отправки.
`revalidatePath` не используется, поскольку повторный GET не вернёт созданную запись.

Автор при создании — фиксированный `userId: 1`. Авторизации и собственной базы нет.

## Тесты и браузерные сценарии

71 unit-тест в пяти файлах покрывает:

- ограничения ввода, пробелы, отсутствующие поля и File вместо текста;
- отсутствие запроса при ошибке валидации, фиксированного автора и сохранение ввода;
- успешный POST, HTTP-ошибки, невалидный JSON/структуру ответа, сетевой сбой и тайм-аут;
- некорректные номера страниц, последнюю и пустую страницы;
- объединение авторов с постами и работу ленты при недоступных авторах.

Для ручной проверки запустить production-сборку и:

1. Перейти на следующую и последнюю страницы; проверить `?page=-1` и `?page=999999`.
2. Отправить пробелы: проверить ошибки Zod, сохранение полей и повторную отправку.
3. Отправить корректный пост: проверить подтверждение API и очистку формы.
4. Проверить Tab-навигацию, фокус результата и кнопку «Написать» на узком экране.
5. Отключить JavaScript, перезагрузить страницу и отправить форму ещё раз.

## Использование AI

С помощью **OpenAI Codex** подготовлены и отрефакторены все исходники приложения:
компоненты, HTTP-клиент, схемы и модели, Server Action, стили и SVG,
конфигурация проекта и CI, unit-тесты и README.
AI также использовался для ревью, поиска ошибок и браузерных проверок.
`package-lock.json` создан npm; служебные типы маршрутов создаёт Next.js.

Проверка сгенерированного кода включала:

- форматирование, ESLint, TypeScript, unit-тесты и production-сборку;
- проверку серверно-клиентской границы и ответов внешнего API;
- реальные GET/POST и пользовательские сценарии в headless Microsoft Edge через Playwright;
- ошибки валидации, сохранение ввода, успешную отправку и блокировку повторного нажатия;
- пагинацию, 404, отсутствие клиентских запросов к JSONPlaceholder;
- ширины 320, 390, 768, 1024 и 1440 px, визуальный просмотр снимков;
- клавиатурную навигацию и работу без JavaScript.

При проверке найдено, что потоковый Suspense оставлял заглушку без JavaScript;
граница была удалена, сценарий перепроверен. Live region отправки вынесен
за пределы `aria-busy`. При рефакторинге удалено CSS-правило `font: inherit`,
перекрывавшее типографические utilities Tailwind.

Браузерные проверки выполнялись внешним локальным Playwright-скриптом.
В репозитории сохранены unit-тесты и ручные сценарии выше; CI не запускает E2E.
Проверка настоящим экранным диктором не проводилась.
